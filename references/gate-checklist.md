# 门禁终检清单（GATE 模式 · D1–D8）

> GATE 模式铁律：**只审不改**。审稿与改稿分离，问题全部进报告，不顺手修。

## 门禁总则

1. 审稿独立：GATE 阶段不得修改文稿任何内容，包括标点
2. 全维扫描：按 D1–D8 逐维过，不跳项；每维给「通过 / Warning / Blocker」判定
3. 结论三档：通过（无 Blocker 且 Warning ≤ 项目限额）/ 有条件通过（仅 Warning，列出带条件放行项）/ 退回（任一 Blocker）
4. 可追溯：每个问题必须定位到节 + 句摘，读报告者不翻原稿也能理解问题

## 检查维度

### D1 文风（AI 腔与套话）

按 clean 模式标准执行：`checklist.md` A 节 H1–H31 + `phrase-blacklist.md` §1–7、§9–12、§18–24 + `delivery-artifact-mode.md` + `production-path.md`（PPT/客户交付必读）+ **`ppt-deck-isomorphism.md`（H31，3–5 页总部/客户 PPT 必读）**。
判级：命中 H1–H8 或禁用词，密集（每千字 >3 处）为 Blocker；零星为 Warning。  
**H9 记忆负担计数**：版式「栏」、三口径/五问/六项等记忆压缩未改内容指称 → 对外请示稿 **Blocker**，内部草稿 Warning；误删「请指示三件事」等功能计数 → **Blocker**。  
**H18–H19 / H25**：对外 PPT 名词堆叠、翻译风框式、欧化长定语/空转动词/假对称半页 → **Blocker**；零星 Warning。  
**H23**：客户交付无中文定稿句证据、Agent 整篇造句灌 PPT → **Blocker**（路径违规）。

### D2 事实一致性（数值冻结表）

操作规程（必须执行，不得凭印象跳过）：

1. **登记**：逐句提取全文的数值、指标名、日期、单位、口径限定词，制成登记表
   （列：序号 / 位置 / 指标名 / 数值 / 单位 / 口径说明）
2. **比对**：与上游材料（原稿、数据源、前一版本）逐项 diff
3. **判定**：
   - 数值、指标名、口径任何变动且无标注依据 → **Blocker**
   - 单位混用（万元/元、%/万分之几）→ **Blocker**
   - 登记表内部自相矛盾（同指标两处数值不同）→ **Blocker**
   - **同页前后矛盾**（如结论写五类、建议写四类；数据写偏高、结论写不高）→ **Blocker**
   - **正文与图注/附录关键读数不一致**（须回源，不得在 GATE 阶段擅自改数）→ **Blocker**
   - 仅有格式差异（全半角、千分位）→ Warning

### D3 引用合规

- 文内 `[n]` 与末尾 Sources 一一对应，无空引用、无幽灵来源 → 缺失为 **Blocker**
- 关键结论无来源且未标「待补充」→ **Blocker**
- 来源信息不完整（缺 title 或 url）→ Warning
- **PPT/请示**：正文不强制「口径：探索结论，对应附录」；须在文末附录备注本次交付材料，且禁止无材料编造数。仅因页内无「对应附录」四字 → **不**升 Blocker（材料已注且可读数可核即可）
- 本项目若无引用规范要求，此维整体标注「不适用」并在报告说明

### D4 结构完整性

- 结论相对输入材料有增量（新结论/新建议/新动作），纯复述 → Warning；关键交付缺结论 → **Blocker**
- 建议句有可执行动作（谁/做什么/依据），「建议关注」「持续优化」类空句 → Warning
- TODO、待填写、占位符、模板残留 → **Blocker**（交付件不允许）
- PPT/请示稿残留：`待补`、文件名式 `-new`、封面「项目名/闭环」工作注记 → **Blocker**
- **H22 交付痕迹**：`需补充完整`、`待试算`、`待补充最新数据`；客户稿残留「仅供内部…不做正式交付」→ **Blocker**
- **H21 数据叙事**：决策页关键指标块无「所以呢」/图表无读图结论且异常无解释 → Warning；影响放行的决策页 → **Blocker**
- 承诺与正文脱节（结论说三章讲四章）→ Warning

### D5 格式规范

- 标题层级跳级或倒挂 → Warning
- 表格无表头、跨页断裂语义、列宽异常 → Warning
- 文件命名不符合项目约定 → Warning（项目有硬性规范时升 Blocker）
- 图片格式、路径、引用有效性 → 失效引用为 **Blocker**

### D6 敏感信息

- 特定机构未公开口径、客户未授权数据、未公开监管信息 → **Blocker**
- 机构专有隐喻/内部黑话未加解释 → Warning
- 本维宁严勿松：拿不准的按 Blocker 处理并在报告标注「待人工判断」

### D7 术语一致性

- 同一概念多种叫法（如「不良率/逾期率/坏账率」混指同物；坏客户/环客户；白户/自户）→ Warning；影响数值理解时升 **Blocker**
- 中英混杂无必要（同一术语中英文交替）→ Warning
- **H20**：客户/业务稿缩写首次出现未展开（无中文全称+人话）→ Warning；≥3 种或表头粘连无法读 → **Blocker**
- 客户正文堆内部规则号（`R40`/`R11`）无业务释义 → Warning；整表皆号无释义 → **Blocker**
- 切点/中间带/样本窗口径前后不一致（如 640 与 645、中间带 640–660 与 640–680）→ 按 D2 升 **Blocker**

### D8 可读性

按 `readability-checklist.md` R1–R7 执行，输出可读性档位（A/B/C）。
判级：C 档（需重排）→ **Blocker**（对外交付）或 Warning（内部草稿）；B 档 → Warning。

## 场景路由表

| 交付件类型 | 检查维度 | 重点 | 默认严格度 |
|------------|----------|------|------------|
| 分析报告 | D1–D8 | D2、D3、D8 | 标准 |
| 会议纪要 | D1、D4、D7 | D4 | 轻量 |
| 策略说明/需求确认 | D1–D8 | D2、D6 | 严格 |
| PPT/演示文稿 | D1–D2、D4–D5、D7–D8 | D2；D1（**H9 + H18–H19 + H25**）；D4（**H21–H23、H27**）；D7（**H20**）；路径/句库 **H23–H24**；分轨 **H26** | 标准（对外/客户交付升严格） |
| 操作指引 | D1、D4、D7、D8 | D7、D8 | 标准 |
| 对外正式交付 | D1–D8 | 全部 | 严格 |

项目覆盖层可配置严格度档位（轻量/标准/严格），未配置时按上表默认执行。

## 放行规则汇总

| 级别 | 定义 | 处理 |
|------|------|------|
| Blocker | 数值口径错误、引用造假、敏感信息、占位残留、可读性 C 档（对外） | 任一命中即退回 |
| Warning | 文风残留、格式不规范、术语不统一、可读性 B 档 | 列出条件，可带条件放行 |
| Info | 优化建议，不影响放行 | 仅记录 |

Warning 限额（标准档）：每千字 ≤2 处可带条件放行；超出按退回处理。严格档限额减半，轻量档翻倍。
