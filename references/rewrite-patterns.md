# 公共改写范式

先冻结数字，再改表述。

## 1. 引号标语 → 直述

```text
改前：支撑从「拒批二元」升级为「一体化决策」
改后：除拒批外，可联动初始额度与复核规则
```

## 2. 破折号 / 箭头 → 平实断句

```text
改前：自动审批通过率 — 64.93%
改后：自动审批通过率为 64.93%

改前：未知段 → 复核
改后：未知段进入复核
```

## 3. 替读者发言 → 数据观察

```text
改前：很多人以为通过率已经够高
改后：当前自动审批通过率为 64.93%
```

## 4. 纠错说教 → 宜不宜或直述

```text
改前：真正的问题不是模型，而是阈值过松
改后：当前低分段通过率偏高，建议复评低分段规则
```

## 5. 教师问答 → 直接建议

```text
改前：那要不要分群？要，而且很重要。
改后：建议按客群分别设定通过分数线。
```

## 6. 空分析 / 空评价 → 指标落点

```text
改前：这一步的核心是做好风险分层
改后：按评分段划分后，低分段不良率为 8.2%

改前：整体优化效果很明显
改后：低分段不良率由 9.1% 降至 8.2%
```

## 7. 隐喻 → 业务直述

```text
改前：线上自动路径是主战场
改后：评分主要服务线上自动审批，该路径申请占比为 82.32%

改前：缺少灰度消化
改后：自动转人工占比偏低，中间分段消化作用有限
```

## 8. 结构标签

```text
改前：【数据】…【怎么做】…
改后：数据：… 结论：… 建议：…
```

## 9. 缺主语压缩句 → 主谓完整

```text
改前：开户后第 2 个月短逾最先集中，3 个月内为准入观察重点，约第 6 个月后趋缓。
改后：首次短逾主要出现在开户后第 2 个月；开户后 3 个月以内是准入与额度观察的重点窗口；约至第 6 个月后，短逾新增趋于平缓。
```

要点：写清「什么现象」「落在哪个时点」「对审批观察意味着什么」；少用无主语的四字压缩。

## 10. 客套需求信 → 依据说明体

```text
改前：致相关同事：为了更好地推进合作，我们希望贵方能够尽快提供收入相关数据，恳请确认。
改后：收入相关取数主要用于新发卡申请与授信核对。请按下列编号反馈是否可提供、可否按申请时点导出。
```

## 11. 「有据 / 我们据此认为」→ 来源依据 + 待确认

```text
改前：有据：培训材料第23页。我们据此认为对方一定存有月收入字段并可导出。
改后：有依据：培训交付件建议额度页列示基本月收入。生产是否落库、可否按申请导出，请确认。
```

```text
改前：证据来源为内部讨论稿，证明对方持有代发数据。
改后：现有手工整理交付件中未见明确表述，请确认是否具备。（内部分析稿不作对方持有数据的来源依据。）
```

## 12. 散文式规则 → 条件 / 计算 / 结果

```text
改前：当客户公积金缴存情况比较正常的时候，其实就可以用月缴金额去除以缴存比例，从而估算出大致的月收入水平。
改后：1.月收入
缴交状态为正常缴费，月缴金额非空且>0。
若缴存比例非空，月收入=月缴金额/（个人缴存比例+单位缴存比例）。
若缴存比例为空，月收入=月缴金额/0.2。
```

## 13. 说教提醒 → 操作指引句

```text
改前：需要特别注意的是，一定要认真核对单位信息，否则容易出错。
改后：核对缴费单位与客户表填单位是否一致；不一致时可结合关联关系作综合判断。
```

```text
改前：缴费基数其实非常有价值，能够深刻反映客户收入。
改后：缴费基数可帮助判断客户基本收入情况。
```

## 14. 未证实结论 → 不宜定论 + 确认后动作

```text
改前：对方定额用的收入肯定不准，行内收入一定更准，额度收入比已经严重超标。
改后：在未取得对方定额所用收入、且未与行内可取收入交叉检验核对前，不宜对额度收入比是否超标、行内收入是否更准等作定论。经确认后，据此更新口径说明表并完成交叉检验核对。
```

## 15. 电报压缩句 → 补连词与标点

```text
改前：无评分17.9%人对33.4%不良余额
改后：无评分户数占比 17.9%、不良余额占比 33.4%

改前：无评分不得自动高额
改后：无评分不得自动授予高额

改前：后文先对三口径
改后：后文先对齐报表、探索全量与新客短窗的数据口径

改前：主/贷款 10:1 后 7:3白户全量训练
改后：主模型与纯贷款户按 10:1 抽样、7:3 切分；白户全量训练

改前：主 17 贷款 15白户 13
改后：主模型 17、纯贷款户 15、白户 13
```

## 16. 主宾搭配 / 语序

```text
改前：有资产、有社保等大体量标签是主评分卡主体客群
改后：有资产、有社保等大体量标签对应的客群构成主评分卡主体

改前：正常申请成功流程缺少征信报告
改后：申请成功且流程正常的件缺少征信报告

改前：但是迁回行内后特有接入的政务数据
改后：但属迁回行内后新接入的政务数据
```

## 17. 歧义动词 / 缩写 → 书面完整

```text
改前：中间带走风险复核并设上限
改后：中间带进入风险复核并设上限

改前：区空不得与连续缴纳同等待遇
改后：缴纳区为空不得与连续缴纳同等对待

改前：早逾预警在进入逾期两期前动作
改后：早逾预警在进入逾期两期前介入
```

## 18. 双口径混读 → 分列写清

```text
改前：白户不良不高，但不宜并入低风险自动审批
改后：白户不良账户占比不高（1.08%），但金额不良率 5.19% 偏高，不宜并入低风险自动审批

改前：金额不良 | 账户占比（同格，易读成样本占比）
改后：金额不良、不良账户占比分列两格（或两句），禁止与样本账户占比混名
```

## 19. 记忆负担计数 → 内容指称（H9）

```text
改前：工作按七栏展开，归为四类：数据诊断、准入、决策、早逾预警
改后：各板块按数据诊断、准入、决策、早逾预警编排

改前：三个口径读数见本页三栏
改后：各口径读数见本页分区

改前：从三口径读当前行内业务数据
改后：分口径读当前行内业务数据

改前：承接五项问题（五问）
改后：承接前面的结构问题诊断

改前：六项配置细项待指示后执行
改后：配置细项待指示后执行

改前：四类对应后文：数据诊断对五项问题；…
改后：各板块对应后文：数据诊断对结构问题；…

改前：三套卡共用开户后 18 个月
改后：分客群评分卡共用开户后 18 个月

改前：…预警。口径：探索结论，对应附录。
改后：…预警。（来源材料见文末附录备注，正文不写套话）
```

保留：`请指示三件事`；`拒绝、复核、通过三段出口`；`报表、探索全量和新客短窗三个口径的汇总数`。

## 20. 问句标题 → 断言式（H10 · 请示/汇报）

对领导的标题应是「本页答案」，不要把答题义务转给读者。

```text
改前：为何把评分卡与策略建设迁回行内
改后：评分卡与策略建设迁回行内自主管理

改前：内外部数据如何对齐并贯穿审批到逾期
改后：内外部数据对齐后贯穿审批到逾期

改前：申请时记录哪些信息
改后：申请时点记录的字段

改前：2 WOE 与 IV 怎么算
改后：2 WOE 与 IV 的计算方式

改前：准入层 问题三与问题五如何约束入口
改后：准入层以全量评分与标准征信约束入口
```

保留：`是否完成评分` / `是否最终发卡` / `是否断缴`（布尔字段名，非问句）。

## 21. 空泛因果 / 强承诺 → 可核对事实（H11）

无机制、无度量的评价动词改为可见事实或工序表述。

```text
改前：严格监控跨行社、多产品共债，对严控风险有积极作用。
改后：跨行社、多产品共债在单一产品视图中不可见；…须单列视图与责任部门监控。

改前：有利于提升行内贷款潜客白名单质量
改后：可生成贷款潜客白名单（承接前文客群主语，勿叠指）

改前：建议 全面推进大数据风控管理；严格禁止…
改后：建议 严格禁止…（删空泛「全面推进」；制度句保留）

改前：相似度筛选保证入模池信息互补。CSI 保证跨年分布不过度漂移
改后：相似度筛选使入模池信息互补。CSI 用于核对跨年分布漂移，通过后再进回归。
```

空展望/空承诺（无数、无动作）删除或仅落原文明示动作，禁止新增原文没有的计划与断言（真实优先，不用编造圆场）。

```text
改前：未来将打造更加卓越的…体系，为…保驾护航，项目前景可期。
改后：删除空展望三连；仅当原文已有具体动作时保留该动作句。

改前：我们将持续优化策略表现。（无数、无动作）
改后：删除；或改写为原文明示的具体动作。
```

保留：`严格禁止` / `不得` / `须`（制度与规则）。

## 22. 生僻行话 → 常用书面词（H12）

```text
改前：逾期 60 天标坏 / 叠加载债 / 缴费排名垫底 / 强拒绝 / 刚扣额度 / 并出分 / 下沉客群 / 这一档只说明
改后：逾期 60 天标记为坏样本 / 叠加债务负担 / 缴费基数排名最低 / 强制拒绝 / 刚性扣减额度 / 给出评分 / 资质较弱客群 / 该报表口径只说明
```

专有名词首现括注示例（全称以用户口径为准）：`中征信（人行征信报告内评分）`；`安全垫（低风险资产缓冲）`。

## 23. 电报导航句 / 跨框断句 / 悬垂口径（H13 · 请示 PPT）

来源审稿：`ppt语气语法审稿_r170_电报句专项.md`（类型：导航标签句 / 索引压缩句 / 图表描述电报句 / 跨框断句 / 悬垂标签）。  
评分工具依赖「承接」「下一页/末页」关键词；可替换「上承/下页」电报壳。

```text
改前：上承户数与余额错配，下页进入 640–660 切分问题。
改后：本页承接户数与余额错配，下一页进入 640–660 切分问题。

改前：承接架构，下页看迁回。
改后：本页承接整体架构，下一页看迁回安排。

改前：对应早逾、剪枝交叉。
改后：本页结论与早逾定标、剪枝交叉两页衔接。

改前：…通过/拒绝分␊布。上承…（跨框切断）
改后：合并为一框：「…通过/拒绝分布」+「本页承接…，下一页…」

改前：图1.3.2 …分布图。口径：
改后：图1.3.2 …分布图（口径：探索结论）
（补全前先看邻框是否已有口径说明，避免重复；非图注悬垂「口径：」可直接删标签）
```

复查清零：`上承`；`下页`+≤6 字标签句；行尾 `。口径：`；索引电报「对应早逾/对应后续」。

## 24. 专业压缩语展开（H14 · 请示/非建模读者）

处长层读者无法解码的建模行话与动宾压缩，须展开；**批量替换时用正则保护已展开词**。

```text
# 入模（先长后短；兜底 (?<!纳)入模(?!型) → 纳入模型）
入模变量 → 纳入模型的变量
入模清单 → 模型变量清单
入模个数 → 纳入模型的变量个数
入模池 → 候选变量池
逻辑回归入模 → 逻辑回归筛选
灰不入模 → 灰样本不纳入模型

# 拆类
难拆不良根因 → 难以定位不良的根本原因
拆出暴露… → 梳理出暴露…
同口径拆开 → 在同一口径下分析
按征信厚度拆开 → 按征信厚度分设

# 压缩动宾（定出口/定标签用 (?<!确) 保护）
定出口 → 确定出口
定标签 → 确定标签
挡不合格件 → 拦截不合格件
打出主评分 → 给出主评分
定额回传额度 → 定额环节确定额度
```

陷阱：`纳入模型`.replace(`入模`, …) → `纳纳入模型型`（撕裂）；复查应用 `(?<!纳)入模(?!型)` 与 `纳{2,}入模型`。

## 25. 偏正压缩名词展开（H15 · 请示 PPT）

双字+双字偏正里删了「的/后的」，处长层要脑补关系——展开观察窗与建设类名词。

```text
短窗 → 短观察窗
长窗 → 长观察窗（长窗暴露/对照/观察 先整词替换）
汇总数 → 汇总数据
人工出口 → 人工审批出口（「自动与人工出口差异」→「自动与人工审批出口的差异」）
建设项 → 建设内容（「可配置建设项」→「可配置的建设内容」）
暴露节奏 → 风险暴露节奏（同句点名时）
```

保留：三段出口、九格出口、分组出口。  
待确认：早逾 → 早期逾期预警（涉及标题，须用户确认）。

陷阱：`汇总数据` 的前三字是「汇总数」——复查须用 `汇总数(?!据)`，勿把「汇总数据」当残留；并检查「汇总数据据」叠字。  
多轮复扫词表：`experience/MULTI_ROUND_CLEAR_SCAN.md`。

## 26. 逾期缩略与无主语条件句（H16）

用户确认后，「早逾」由待确认改为必改。

```text
早逾预警 → 早期逾期预警
早逾定标 / 早逾定标签 / 早逾确定标签 → 早期逾期定标 / …确定标签
短逾不作贷前硬拒绝 → 短期逾期不作贷前硬拒绝
过短则尚未显现…，过长则样本偏旧…
  → 表现期过短时，坏客户尚未显现…；表现期过长时，样本偏旧…
```

兜底：`早逾`→`早期逾期`、`短逾`→`短期逾期`（「早期逾期/短期逾期」内无连续二字，可安全替换）。  
复查：`(?<!期)早逾`、`(?<!期)短逾`、`过短则`、`过长则`。

```text
# 逾期家族
首逾率 / 首逾窗口 / 人工首逾 / 首逾 → 首次逾期率 / 首次逾期窗口 / 人工首次逾期 / 首次逾期

# 动宾同型（以稿面用词为准，指令写「调规则」时稿面可能是「调阈值」）
改卡、补数 → 修改评分卡、补充数据
可改卡、调阈值 → 可修改评分卡、调整阈值
定额封顶 → 定额设上限
矩阵列序 → 矩阵的行列顺序
看出入差异 → 看出口差异

# 术语统一
共贷 → 共债（与 P50「共债」对齐）
```

## 28. 名词堆叠电报体 → 完整流程句（H18）

```text
数据诊断，准入约束入口，决策约束交叉复核与定额，早期逾期确定不良标签定义，分析结果写回策略配置。
→ 先做数据诊断；在准入环节设置约束入口；在决策环节用交叉复核和定额控制风险；用早期逾期定义不良标签；最后把分析结果写回策略配置。

项目目标：压降新客金额不良率，建设评分卡、优化策略与定额、闭环迭代
→ 本项目要压降新客金额不良率。路径是建设分客群评分卡，优化准入与定额，并持续迭代监控。

数据诊断发现问题汇总
→ 新客不良暴露偏慢，短期窗口会低估风险
```

页级结构：标题=结论句；正文≤3 点，每点「判断 + 读数/证据 + 含义或动作」。

## 29. 翻译风 → 中文流水句（H19）

```text
通过采用先进技术手段，以实现运营效率的显著提升。
→ 用上更好的技术，把运营效率提上去。

须用对齐后的行内与外部数据分项统计。
→ 要把行内和外部数据按同一口径对齐后，再分项统计。

优化后模型相对现行评分呈现三点差异。
→ 和现行评分相比，优化后模型有三个明显变化。

经营安全垫（低风险资产缓冲）客群。
→ 重点经营低风险、能起缓冲作用的客群。

在缺乏足够信息的情况下 / 由于…的原因 / 对于…而言
→ 信息不够时 / 因为… / 对…
进行讨论 / 做出决定 / 对…进行优化
→ 讨论 / 决定 / 优化…
```

## 30. 缩略语墙 → 首次解释 + 表头拆列（H20）

```text
建模AUC建模KS跨期验证KSPSI
→ 表头分列：建模 AUC | 建模 KS | 跨期 KS | PSI

KS 0.596，PSI 0.085（客户正文首次）
→ KS（区分度指标，越高排序能力越强）0.596；PSI（评分分布稳定性，越低越稳）0.085

→ 信息不可核验类：未参保、资产低、征信缺失（规则编号见附录）
```

## 37. 翻案腔方向判据与复扫（v5.13）

scan 规则 `AI否定排比` 已扩到 12 形态。改不改按方向判据裁决，不是见词就拆：

**方向判据：看后半句 Y 与前半句 X 的关系。**

- Y 比 X **具体**（纠正误解、排除歧义、区分两个动作）：保留含义，只改外壳，区分仍须完整。
  「这不是退款，而是撤销尚未结算的授权」→「本次操作会撤销尚未结算的授权，不属于退款」。
- Y 比 X **宏大**（拔高、抬轿）：拆掉，直接陈述具体事实。
  「这不仅是一次技术升级，更是一场理念的革新」→「这次改的是调度算法」。

**12 形态**（与 scan 正则一致）：不仅仅是…(而|更)是 ／ 这不只是…(而|还)是 ／ 与其说…(不如|倒不如|毋宁) ／ 并非…而是 ／ 不在于…而在于 ／ 表面(上)…其实|实际|实则 ／ 看似…其实|实际|实则 ／ 以为…其实|才发现|才明白 ／ 回头(看)才发现|明白|知道 ／ 恰恰相反 ／ 从来不是…而是 ／ 「A 不重要，(真正)重要的是 B」。

**保护**：真实引用、固定定义、事实纠错、范围排除、改写后会产生歧义的表达。

**复扫（换壳仍算残留）**：改后出现「问题不只在…」「涉及的却是…」「构成…而非…」、分号改写的先压后抬关系，按同骨架处理。仅删除「既 / 也 / 更」而把三项留在同一句，不算完成改写。

## 38. 语义保真改法（v5.13）

- **强度不升级不降级**：拆「进行 / 实现 / 体现」外壳时，壳内强度原样保留。「体现了流程优化」→「流程做了优化」，不得写成「优化了流程」。
- **排除关系改法**：「不能归因于 A」→「不能用 A 来解释」（保留排除范围）；不得写成「与 A 无关」或「A 一直成立」。
- **因果三分**：原文只有先后 / 相关时，改写不得引入「于是 / 因此 / 促使」；需要表达顺序时用「同期」「其后」等时序词。
- **概括回落具体**：同段已有具体数值时，「显著提升」→ 引用该数值；原文无数值时只恢复动词，不编数字。
- **贴金换后果**：「标志着行业进入规范化阶段」→ 用原文已述的具体后果替换；原文没说后果，整句删，不换词硬留。
- **删而不换**：过渡套话（综上所述 / 与此同时 / 由此可见）删除后读下句能否自立；能自立就删，不换成「总之 / 说到底」（换马甲不算改）。
- **动宾搭配自检**：机械替换后把动宾短语单独念一遍，搭配别扭就重说整个分句，不硬换（「打造方案」→「拿出方案」，不是「做出方案」）。
